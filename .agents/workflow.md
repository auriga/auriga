# エージェント作業ルール

## 優先順位

1. ユーザーの明示的な指示
2. ルートの `AGENTS.md` と `.agents/` 配下のルール
3. リポジトリ内の既存実装・ドキュメント

## 作業の進め方

- 依頼範囲のファイルだけを変更する。
- 既存スタイルを優先し、勝手にアーキテクチャを変えない。
- 調査が必要なら、まず `doc/` と該当モジュールの周辺コードを読む。
- 長時間かかるコマンドや破壊的操作の前に、必要なら確認する。
- 応答は簡潔に。ユーザー向けの説明は日本語で行う。

## やってよいこと

- バグ修正、機能追加、ドキュメント更新（依頼された範囲）
- ビルド・既存スクリプトの実行（調査・検証のため）
- 関連する `doc/` や `CHANGELOG.md` の更新提案・実施（変更内容に応じて）

## 確認してから行うこと（Ask first）

- git のコミット / push / PR / ブランチ作成・削除
- デフォルトの `PACKETVER` や主要ビルドマクロの変更
- 広範囲のリファクタ、ファイル大量移動・リネーム
- 依存関係や CI ワークフローの大幅変更

## やってはいけないこと（Never）

- 依頼外のファイルへのついで書き
- `conf/` 内の認証情報・サーバ間パスワード等の不用意な変更・コミット・ログ出力
- 秘密情報のコミット
- ユーザー未承諾の force push や履歴の破壊的操作
- サードパーティ由来コード（`src/common/lua/`、`src/common/zlib/` など）の不要な改変
