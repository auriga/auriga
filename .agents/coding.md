# コーディング・変更ルール

## 共通

- 既存の命名・インデント・コメント（多くは日本語）のスタイルに合わせる。
- 大規模リファクタや、依頼と無関係な整形・リネームはしない。
- 不明点は推測で仕様を決めず、`doc/` と周辺の既存実装を先に読む。

### ファイルエンコード

- 既存ファイルの**文字エンコードは変更しない**。編集後も元のエンコード（多くは Shift-JIS / CP932）を維持する。
- エディタやツールの既定で UTF-8 に変換して保存しない。UTF-8 への一括変換・BOM 付与もしない。
- 日本語コメント等を追加・修正するときも、対象ファイルと同じエンコードで保存する。
- エンコードを変えると MSVC の C4819 警告や文字化けの原因になる。意図的なエンコード変更はユーザーが明示したときのみ行う。

## ソースコード（`src/`）

- 言語は **C11**。
- 機能ごとにファイルが分かれている。変更時は関連箇所を横断して確認する。
  - 例: `battle.c` 戦闘、`clif.c` クライアント通信、`script.c` スクリプトエンジン、`npc.c` NPC
- パケット処理を触るときは `doc/client_packet.txt` / `doc/inter_server_packet.txt` などを参照し、`PACKETVER` 分岐を壊さない。
- `src/common/lua/` と `src/common/zlib/` はサードパーティ由来。不要な改変は避ける。
- ビルドオプションやパケット版のデフォルト変更は影響が大きい。必要性が明確なとき以外は変えない。

## 設定・データ・スクリプト

| 変更対象 | 参照ドキュメント | 注意 |
|----------|------------------|------|
| `conf/` | `doc/conf_ref.txt` | ローカル差分は可能な限り `conf/import/` |
| `db/` | `doc/db_ref.txt`, `doc/item_bonus.txt` | ID 衝突・既存定義との整合 |
| `script/` | `doc/script_ref.txt` | `map_auriga.conf` 等での読込登録も忘れない |
| SQL | `doc/sqllogin.txt`, `sql-files/` | スキーマ変更時は `*_changetable.sql` を追加する慣習 |

## ドキュメント・変更履歴

- ユーザー向けの挙動変更や重要な修正は `CHANGELOG.md` に追記する。
- エントリ書式は既存に合わせる（番号・日付・作者・箇条書き・関連ファイル名）。
- 仕様の詳細説明は `doc/` 側を更新する。
