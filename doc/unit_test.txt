==========================================================================
 ユニットテスト
--------------------------------------------------------------------------

Auriga のユニットテスト手順です。フレームワークは ThrowTheSwitch Unity
（純 C）を third_party/unity に同梱しています。


--------------------------------------------------------------------------
1. 実行方法

	make test

ルートの Makefile から tests/ をビルドし、テストバイナリ unit_tests を
実行します。失敗すると非ゼロで終了します。

クリーン:

	make test-clean

（または make -C tests clean）


--------------------------------------------------------------------------
2. 構成

	third_party/unity/   Unity 本体（unity.c / ヘッダ / LICENSE）
	tests/               テストソースと Makefile
	tests/stubs/         本番以外のスタブ（malloc 等）

本番サーバーのビルド（make / make sql）とは独立です。
src 以下の本番 *.o はリンクしません（main / グローバル初期化の衝突回避）。


--------------------------------------------------------------------------
3. 初回スコープ

対象は src/common の純粋関数から開始しています。

	md5calc … MD5_String / MD5_Binary（既知ベクトル）
	utils   … auriga_strlcpy / auriga_strlcat / strtobxul

map の戦闘・スクリプト・ソケット等は後続課題です。


--------------------------------------------------------------------------
4. スタブについて

md5calc / utils は malloc.h の aMalloc_ 系を参照します。
テストでは tests/stubs/malloc_stub.c が標準の malloc/free にマップします。
本番の memmgr は使いません。


--------------------------------------------------------------------------
5. CI

GitHub Actions の unit-test-linux-gcc.yml が Linux 上で make test を実行します。
既存のサーバービルド用 workflow とは別ジョブです。


--------------------------------------------------------------------------
6. テストの追加

	1. tests/test_*.c にテスト関数を書く
	2. tests/test_main.c で宣言し RUN_TEST する
	3. 必要なら tests/Makefile の LOCAL_OBJS にオブジェクトを足す
	4. make test で確認する
